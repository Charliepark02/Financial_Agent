# Phase 4 architecture

The default CLI starts FinancialAgent. AgentState owns the request ID, state transitions, tool-call limits, messages, results and timing. ContextManager keeps the system prompt and active tool round together and drops older turns first. Overflow in the required current turn raises ContextBudgetError. Token estimates use character heuristics; Ollama prompt evaluation counts are the comparison reference.

LLMClient calls local Ollama. Conceptual questions use the standard chat path. For market requests the model selects registered tools; Python validates their arguments. ToolRegistry normalizes ticker symbols and defaults, shares concurrent identical requests, and keeps successful results for 60 seconds. Independent calls use up to four workers per batch, in submission order. Each owner of a cache miss applies one retry policy to external work. HTTP timeouts bound transport operations; a running worker can outlive a caller interruption. RetryPolicy defaults to three total attempts, 0.25 seconds base and a four-second delay cap. Each delay doubles with jitter. A longer provider Retry-After ends the attempt instead of retrying early. Ollama uses a 120-second transport timeout; historical price requests specify ten seconds. Neither is a wall-clock deadline for an entire request.

Tool messages contain a rendered, allowlisted report. The final market response takes its asset, date, units, signed metrics and assumptions from the tool result. Tool failures produce unavailable entries. Conceptual prose still comes from the model. A synthetic claim that has no matching observation is unverified. There is no order execution tool. The report is a historical close, and its observation date may precede today. The seven-day annotation is a calendar heuristic, not a trading calendar.

For explicit multi-task use, plan REQUEST creates a FinancialPlanner plan. Malformed JSON or invalid tasks trigger at most one regeneration before execution. PlanningAgent runs normalized independent tasks and renders results directly. The default engine retains multi-round tool selection for follow-up work.

Streaming uses the same controller as ordinary chat. The transport buffers until Ollama sends a completed response before dispatching tool calls. Final report lines are yielded only after validation. Request TTFT is time from chat start to the first nonempty model text across streaming calls; a tool-only response can have no text. Visible latency includes validation and can approach total latency. TPOT is Ollama generation seconds per output token. Throughput is its reciprocal. No TTFT is inferred from a non-streaming response.

Working state lasts one request. Short-term conversation context lasts one process. Opt-in episodic records in SQLite survive restarts. One transaction writes each request, with a schema version and symbol/date index. Only verified financial fields are archived; raw prompts and free-form external prose are omitted. The default path is ~/.financial-agent/analyses.sqlite3. Local account file permissions protect this unencrypted database. Explicit historical retrieval uses recency ordering, exact tickers, optional date/session filters and a 512-estimated-token budget. It does not call an LLM or turn historical data into a fresh quote.
